## What is NOT in the zip (intentional)

- `.env`     — contains a real secret; must be created fresh from `.env.example` in the new workspace.
- `dist/`    — build output; regenerated by `npm run build`.
- `node_modules/` + `package-lock.json` — regenerated by `npm install`.

## Import steps in the fresh Emergent workspace

Assuming the new workspace is pulled from GitHub `disccartindia-arch/vastu-arya-backend @ main` (`660aa17`):

1. **Upload the zip** into the new workspace root (drag & drop, or use the file upload).
2. **Extract** it. All files land at the correct paths — modified files simply overwrite existing ones, new files are added.
3. **Install dependencies:**
   ```bash
   cd /app/backend        # or wherever the workspace roots the repo
   npm install
   ```
4. **Compile check:**
   ```bash
   npx tsc --noEmit
   ```
   Expected: `Exit code: 0`.
5. **Copy env template + fill values:**
   ```bash
   cp .env.example .env
   # then edit .env — at minimum set:
   #   MONGO_URI, JWT_SECRET,
   #   RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET,
   #   EMERGENT_LLM_KEY   (or GEMINI_API_KEY / ANTHROPIC_API_KEY as fallback),
   #   SMTP_* + ADMIN_NOTIFICATION_EMAIL,
   #   CLOUDINARY_*
   ```
6. **Local run (optional):**
   ```bash
   npm run dev          # ts-node, no build needed
   # or
   npm run build && npm start
   ```
7. **Save to GitHub** on the new workspace → **Create New Branch** → name it `feature/backend-production-update` → push.
8. On GitHub, open a PR from `feature/backend-production-update` into `main`. Verify "Able to merge" (should be clean — the export was taken from a workspace whose HEAD == `origin/main` == `660aa17`).
9. Merge the PR → Render auto-deploys.
